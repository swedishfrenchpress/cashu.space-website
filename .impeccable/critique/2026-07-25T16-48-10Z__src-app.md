## Design Specificity Verdict

**Authored for Cashu — could not ship on another product unchanged.** The ornament *is* the subject: Fig. 01 renders a 2,101-sat balance as its real binary denomination set with a real keyset id; the Tokens plate carries a decodable TokenV4 whose decoded proof matches the code pane; the Spec plate excerpts the actual NUT registry with an honest "27 more" continuation; the 404 answers `nut:404` / "Not specified." Registry counts are derived from the data, so the site cannot drift out of sync with itself. Persuasion by verifiability — exactly right for this audience.

Two soft spots: the skeleton is recognizably warp.dev (intentional north star; the monochrome translation mostly transcends it), and the **press band + bento are the most generic surfaces** — card titles like "Bearer token" could sit on any fintech page, and the four bento line-figures (globe, banknote, envelope, wallet) are clip-iconography on a page where every other figure is real spec data.

**Deterministic scan:** near-clean. CLI: 3 findings — 2 `broken-image` hits are static-analysis false positives (JSX-expression `src` on deliberate plain `<img>` for SVGs; runtime overlay confirmed both render), 1 advisory `codex-grid-background` on `.feature-demo__view::before` (globals.css:1735) is the sanctioned drafting-sheet ground of the RFC plates — fired correctly, judged in-doctrine. Runtime overlay: 7 warnings on the homepage — 3 `line-length` (86ch video-feature lead, 121ch dark-theme lead, 136ch footer disclaimer — the disclaimer is DESIGN.md's stated exception; the two `t-body-lead` breaches of the 65–75ch rule are real), 3 `heading-rhythm` (press-card h3s sit 20px below their image vs 37–43px above the standfirst, reading as bound to the wrong block), 1 `first-viewport-column-overflow` (`.feature-scroller__body` column runs 166% of the viewport in the first screen — corroborates the arrival-experience issue). `/wallets` and the 404: zero findings.

## Overall Impression

The statics are excellent and the doctrine is real: one type ramp, one hairline grammar, honest protocol data everywhere, an accessibility skeleton beyond landing-page norm. What drags the experience down is almost entirely **dynamic behavior** — the reveal system makes a site about permanence and craft repeatedly look broken on arrival — plus a conversion path that thins out exactly at its finish line (`/wallets` has no ending and no decision support). The single biggest opportunity: make type instant and reserve motion for the two artifacts that depict protocol behavior.

## What's Working

1. **Honest-content doctrine, executed.** Real NUT numbers, decodable token, matching keyset ids across plates, counts derived from data. The audience this targets will check — and it holds up.
2. **The two-register document system.** Captioned figure plates vs file-strip code panes is an original, ownable pattern; Fig. 02's balance-sheet explains custody risk better than a paragraph could.
3. **Accessibility skeleton.** Working skip link styled as a doctrine slab, `aria-pressed`/`aria-current`, narrating `role="img"` labels, `inert` on hidden views, prefers-reduced-motion handled everywhere including the canvas.

## Priority Issues

**[P1] Jump-arrival invisibility — the reveal system fights the page.**
- **What:** After any non-continuous arrival (nav anchor click, keyboard jump, fast wheel, initial load) sections render blank or ghosted for 1.5–4s. Verified: "Five implementations, one spec." as two viewports of pure black; bento cards 2–4 absent 2.5s after jump; 404 near-blank at 2.5s in dark; `/wallets` header still dim at 4s on mobile. Root cause in `src/components/reveal.tsx`: IO callbacks + staggered delays (~480ms) + 620–880ms transitions stack; the `top < 0` rescue only catches elements above the viewport. Corroborated by the detector's `first-viewport-column-overflow`. **Related hard fail: without JavaScript the entire site is permanently invisible** (unconditional `.reveal { opacity: 0 }`, no noscript fallback) — bitcoin.org renders without JS; this site should too.
- **Why it matters:** The persuasion strategy is craft = credibility; moments that read as "dead page" are direct trust withdrawals, and they hit the highest-intent paths (nav jumps, 404).
- **Fix:** When the first IO callback finds the element already intersecting, add `is-revealed` with zero delay and a ≤200ms fade; cap stagger accumulation per viewport; reveal anchor-target sections immediately; add a noscript/no-JS fallback. Consider reserving entrance motion for the terrain band and draw-on figures only — type should be instant, the way a spec simply *is* when you open it.
- **Suggested command:** /impeccable animate (re-choreograph), then /impeccable harden (no-JS fallback).

**[P1] `/wallets` has no ending.**
- **What:** `src/app/wallets/page.tsx` renders SiteHeader + directory only — no closing CTA, no SiteFooter, no disclaimer. The page dead-ends at "Orchard / OPEN".
- **Why it matters:** DESIGN.md says the twilight band closes every page; this is the conversion-critical route, and it loses the mint-risk language and the spec CTA exactly where a wallet-chooser needs them. It's also the page most likely to be a visitor's last.
- **Fix:** Append the closing-CTA band + `<SiteFooter />` to the wallets page.
- **Suggested command:** /impeccable polish.

**[P1] The wallet decision point has no decision support.**
- **What:** The Mobile group lists 6 wallets (Cashu.me, eNuts, Macadamia, Minibits, Numo, Sovran) as name + destination host only. The only >4-option decision point on the site, served with zero differentiating metadata.
- **Why it matters:** PRODUCT.md's top success metric is "installed a wallet"; a first-timer cannot pick without opening six external sites. Choice paralysis at the finish line.
- **Fix within doctrine:** one mono metadata field per wallet-row (e.g. `iOS / Android`, `open source`) in the existing host register — data, not badges; no color, no icons. Optionally sort by a stated fact rather than false-neutral alphabetical.
- **Suggested command:** /impeccable clarify.

**[P2] Mobile (390px) collisions in the demo panel.**
- **What:** (a) Fig. 01's caption wraps to three lines and runs under the floating FIGURE/CODE toggle; (b) the pillar jump-row truncates at "03 SPEC" — "04 TOKENS" is off-screen with no scroll affordance.
- **Why it matters:** The demo panels are the site's proof artifacts; on mobile the proof gets sat on by a control, and a whole pillar disappears.
- **Fix:** At the narrow breakpoint let the toggle sit in flow below the caption; add an edge-fade mask or partial-item peek to `.feature-nav`.
- **Suggested command:** /impeccable adapt.

**[P2] Wayfinding and labeling inconsistencies.**
- **What:** `id="implementations"` wraps the Properties bento, so nav "Implementations" (and keymap `g i`) scrolls to a section titled "Properties of the protocol" while the actual registry sits two sections later. Keymap `g s` opens `github.com/cashubtc/nuts` while every visible Spec CTA opens `docs.cashu.space`. Homepage says "Five implementations"; `/wallets` lists four. Nav links carry no active-route state. Keymap dialog opens with Chrome's default blue focus ring (a No-Colour leak); focus on the active FIGURE/CODE segment is invisible (edge outline against ink fill).
- **Why it matters:** Each is small; together they erode exactly the "one canonical document" authority the design claims — and the site's own audience audits details.
- **Fix:** Move the anchor id to the registry section (or retitle the nav item); unify `g s` with the visible Spec target; reconcile the count; style `dialog:focus-visible` and invert the pressed-segment ring.
- **Suggested command:** /impeccable polish.

## Questions to Consider

1. If restraint is the brand, why does every element still enter through an animation? Paper doesn't fade in. What if type were instant and motion reserved for the two artifacts that depict protocol behavior?
2. Where is Fig. 00? No plate ever shows the blind signature itself — the one idea that makes Cashu Cashu. A captioned blind-sign → unblind → spend figure could be the site's signature artifact *and* Jordan's missing 101 (and would let the clip-art bento envelope retire).
3. Should the wallet registry state a sorting fact? The site already curates (8 wallets, not 30). Is "reference implementation" / "most-used" in mono more honest than an alphabetical list that forces users to choose blind?
